# 技能 Tag 检索器（tagsearch）

按 **Tag**（标签）离线检索 DOTA2-WIKI 技能条目的本地工具。纯静态页面，双击 `index.html` 即用，检索过程无需联网、无需后台。

> **仓库只含代码，不含数据快照。** `data.js` / `_raw.json` 已写入 `.gitignore` —— 数据源为 DOTA2-WIKI 后台（`partner.dota2.com.cn`），需具备该后台账号与登录态，且**不随本仓库分发**。首次使用请先按「四、更新数据」抓取一次。
>
> **抓取依赖**：[bsk（browser-skill）](https://github.com/Tencent/BrowserSkill) CLI + 已登录后台的浏览器。仅做检索则无需这些依赖。
>
> 本项目为个人自用工具，非官方产品；DOTA2 及相关内容版权归 Valve 与对应权利方所有。

## 一、功能

| 能力 | 说明 |
|---|---|
| **单 tag 检索** | 输入一个 tag（如「治疗」），列出全库所有包含该 tag 的技能 |
| **且（AND）** | 最多 5 个 tag，技能须**同时**包含全部 |
| **或（OR）** | 最多 5 个 tag，技能包含**任一**即可。**至少 2 项**才有意义 —— 只填 1 项时等价于「且」，界面会实时提示 |
| **反选（NOT / 排除）** | 最多 5 个 tag，技能含**任一**即被剔除 |
| **三类组合** | 最终条件 = （且 全部满足）且（或 至少一项）且（非 全部不满足）。三类**可任意搭配、同时生效** |
| **实时条件表达式** | 条件区下方实时显示最终表达式，如 `(且 防御塔) 且 (或 治疗 或 沉默) 且 (非 定值生命恢复)`，随时确认组合是否按预期生效 |
| **模糊匹配** | 勾选后按子串匹配（如输入「防御塔」→ 自动扩展为「友方防御塔」「敌方防御塔」及其各档位） |
| **匹配范围** | 可分别限定在 技能类型 / 技能效果 / 技能特性 / tags 字段 |
| **默认排除非技能条目** | 检索时**自动跳过**三类非正常条目（见下节）：废弃条目（名含「废」）、自定义技能（id ≥ 20000）、公式残条（名以「-{」开头）。勾选「包含被排除项」可临时放回，此时这类行**灰显并标注原因** |
| **简 / 详 展示切换**（结果区上方） | 默认**详细**（升级项 / 技能 / ID / 命中详情 / tag 数 / 详情）。点「☰ 简洁展示」切换为**自适应流式列表：每个技能 = 一个不可拆分的块（升级图标 + 技能名）**，按浏览器宽度自动决定每行放几个（实测 ≥1100px 约 6 个/行、760px 4 个/行、420px 2 个/行；行高 24px），便于快速通读整批命中；技能名仍可点击查看详情。再点一次复原 |
| **结果明细** | 逐技能显示命中的 tag 落在**哪个字段、哪一行效果**；点「详情」查看该技能全部 tag。**命中「技能特性」时，chip 内直接展开该特性的内容**（虚线分隔 + 特性名 + 完整描述句），详情弹窗的「技能特性（机制项）」区同样逐条列出内容 |
| **升级项展示** | 结果表**第一列（技能左侧）**为「升级项」，**上图标、下中文名**（如「15级左天赋」，= 网页条目名去掉尾缀「升级」），标出该技能涉及的**升级来源**（神杖 / 魔晶 / 天赋 / 命石 / 饰品 / 其他）；悬停看网页全名与 wiki 占位符写法；详情弹窗顶部同步列出 |
| **导出 CSV** | 导出全部命中结果（含升级项、升级项占位符、命中位置），Excel 可直接打开 |
| **图标资源** | 10 个升级项图标置于 `icons/`（`<id>.png`，来自 wiki 资源 `img.dota2.com.cn/dota2wiki/...`），本地优先、失败自动回退在线地址；无图标的 3 项用 wiki 同款纯色块 |
| **更新本地数据**（右上角） | 一键从 partner 后台抓取最新 Tag/技能数据 → 就地重建索引 → 下载新的 `data.js` |

> 同名 tag 分属多个档位时（如「友方防御塔」有 目标 / 神杖升级目标 / 魔晶升级目标 / 天赋升级目标 四档），**命中任一档即算包含**。
>
> **关于「或」的项数**：「或」的语义是 *至少满足其一*。只填 **1 项**时它退化为「必须包含该项」，与「且」完全等价（实测：`或:防御塔` = `且:防御塔` = 14），不构成「或」。因此「或」至少要填 **2 项**；只填 1 项时表达式条与结果区会给出提示，**但不阻断检索**（结果本身是正确的）。

> **关于「升级项」**：升级来源（神杖 / 魔晶 / 天赋 / 命石 / 饰品 / 其他，共 13 项）在后台是挂在**技能效果行 `effect_tag`** 上的 tag，故「某技能有神杖升级」= 它的某个效果行带「神杖升级」tag。工具会把整条技能涉及的升级项去重汇总成一列。全库 **248 / 3303** 条技能带升级项（神杖 72、魔晶 68、天赋若干、其他 8、饰品 4、命石 2）。

>
> | 升级项（网页条目名） | id | 界面显示名 | 占位符 | 图标 |

## 二、文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 主界面（打开它即可使用；缺 `data.js` 时会给出抓取提示） |
| `data.js` | **数据快照**（脚本生成，**不入库**）：Tag 定义 + 全部技能的 tag 数据 |
| `search-core.js` | 检索核心逻辑（与界面分离，可被 Node 复用） |
| `icons/` | **升级项图标 10 个**（`1046.png`…`1055.png`，40×40 / 64×64） |
| `refresh.sh` / `refresh.bat` | **一键刷新数据**（重新从后台抓取） |
| `scripts/fetch_tagdb.js` | 页面内抓取脚本（由 `refresh.sh` 通过 `bsk evaluate` 注入执行） |
| `build_data.py` | 把 `_raw.json` 转成 `data.js`（含技能特性内容池化） |
| `_raw.json` | 最近一次抓取的原始返回（**不入库**） |
| `selftest.js` | 逻辑自测（Node 运行） |
| `uitest.js` | 界面回归测试（jsdom） |
| `serve.py` | **本机服务**：静态托管 + `POST /api/refresh` 一键更新数据 |
| `start.bat` | 启动本机服务并打开页面（推荐入口） |

## 三、使用

> **首次使用**：本仓库**不含数据快照**。双击 `index.html` 若提示「未找到数据文件 data.js」，请先按第四节抓取一次（需 bsk CLI + 已登录后台的浏览器）。已拿到 `data.js` 后，后续使用完全离线。

1. 双击 **`index.html`**（推荐 Chrome / Edge）。
2. 在左侧「必须包含 / 至少包含一项 / 必须排除」中输入 tag 名称（有自动补全）。三组可**同时填写**，左下「当前条件」会实时显示组合后的表达式。
3. 按 <kbd>回车</kbd> 或点「检 索」。
4. 结果区右上角可切换 **「☰ 简洁展示」/「▤ 详细展示」** —— 简洁模式每个技能是**一个整体块（升级图标 + 技能名）**，由浏览器**按窗口宽度自动决定每行放几个**（窗口越宽一行越多），换行时**整块一起换行、图标不会和技能名分离**，适合快速通读；详细模式含 ID、命中详情（落在哪个字段/第几行效果）与 tag 数。切换**不重新检索**，就地重渲染。

**示例**

| 目标 | 输入 | 命中 |
|---|---|---|
| 所有含「防御塔」的技能 | 且：`防御塔`（勾选模糊匹配） | 14 |
| 含防御塔但**不含**定值生命恢复 | 且：`防御塔`　非：`定值生命恢复` | 13 |
| 含防御塔**或**定值生命恢复 | 或：`防御塔` + `定值生命恢复` | 44 |
| 含防御塔**且**（治疗或定值生命恢复） | 且：`防御塔`　或：`治疗` + `定值生命恢复` | 2 |
| 三类同时用 | 且：`防御塔`　或：`治疗`　非：`定值生命恢复` | 1 |

> 命中数会随站点数据更新变化，上表基于 **2026-10-16 20:10** 数据快照。
> 「或：防御塔\|定值生命恢复」含被排除项时是 **45** —— 差的那 1 条是 **6598 热血竞技场（废）**，属废弃条目，已被默认排除。

### 默认排除的非技能条目

全库 3303 条技能记录里，有 **536 条不是正常技能条目**，检索时**默认跳过**（勾选左侧「包含被排除项」可临时放回，此时这些行会**灰显并标注原因**）：

| 类别 | 判定 | 条数 | 例子 |
|---|---|:--:|---|
| 废弃条目 | 名称含「废」 | 9 | `6598 热血竞技场（废）`、`5368 贪魔的贪婪（废）` |
| 自定义技能 | id ≥ 20000 | 312 | `20303 +253攻击力`、空名条目 |
| 公式残条 | 名称以「-{」开头 | 215 | `7891 -{s:value}秒 雪球冷却` |

三类**互不重叠**，合计 536 条 → **参与检索的有效技能为 2767 条**（顶部「技能」指标显示为 `2767（有效，共 3303）`）。结果区顶部会实时提示本次排除了多少条。

> 另有 162 条**空名**条目（id < 20000，不属上述三类），但它们**全部不含任何 tag**，检索中永远不会命中，故无需额外排除。

## 四、更新数据（页面右上角「⟳ 更新本地数据」）

数据来自后台「Tag 管理」与「技能」接口，属**已审核版**内容。三种更新方式（面板内按 ①②③ 排列）：

| 方式 | 操作 | 适用 |
|---|---|---|
| ① **一键更新** | 双击 **`start.bat`**（启动本机服务并打开页面）→ 点「开始更新」 | 常规推荐 |
| ② **重新抓取** | 双击 **`refresh.bat`** → 回页面点「重新加载 data.js」 | 只想刷新数据、不想开服务 |
| ③ **离线替换** | 面板里「选择文件载入…」，读入 `data.js` 或 `_raw.json` | 别人给的快照 / 离线环境 |

① 成功后会：抓取 → **服务把新快照写入本目录 `data.js`** → 页面就地重建索引（无需刷新）→ 并**下载一份 `data.js`**。
若浏览器把下载挂在「下载气泡」里等确认（`.crdownload`），直接用目录里那份即可——它已是最新。

**前提**（四项都要满足）：
1. 已安装 [bsk（browser-skill）CLI](https://github.com/Tencent/BrowserSkill)，且 `bsk` 在 `PATH` 中（或用环境变量 `BSK_EXE` 指定路径）；
2. `bsk daemon` 在运行 —— 以**能长期存活**的方式启动（不要用 `&`）：`bsk daemon start --foreground --session-idle 30m --daemon-idle 30m --port 52810`；
3. 浏览器已安装 browser-skill 扩展并处于 **connected** 状态；
4. 该浏览器**已登录 partner 后台**。

抓取时你**自己开着的 wiki 页面不受影响**（bsk 在它自己的受控标签页里导航并抓取）。无需 bsk 会话时脚本会尝试新建；若失败，先手动执行 `bsk session start` 再重试。

> ⚠️ **为什么页面不能自己抓接口**（10-16 实测结论）：接口虽然回显任意 `Origin` 且 `Access-Control-Allow-Credentials: true`，但登录 Cookie 是 **SameSite=Lax**，浏览器**不会**把它发给跨站请求 —— `file://` 与 `http://127.0.0.1` 两种打开方式都拿到 `{"code":1001}`（未登录）。所以必须在**已登录的 partner 页面内**执行抓取（即 bsk 那条路），本机服务只是把这件事接到按钮上。

服务地址默认 `http://127.0.0.1:8899`，页面会自动探测（同源 → 上次成功 → 默认端口）；换端口启动时在面板里改地址并「测试连接」。

### 命令行等价操作

```bash
bash refresh.sh          # 抓取 + 重建 data.js（走 bsk）
python serve.py --open   # 启动本机服务（含一键更新接口）
curl -X POST http://127.0.0.1:8899/api/refresh    # 直接用接口触发更新
```

## 五、数据来源与结构

- **Tag 全量**：`/apg/admin/mechanism/list`（973 条：目标 249 / 机制 705 / **升级 13** / 图标 6）
- **技能全量**：`/apg/admin/hero/ability`（3303 条）

技能记录中 tag 的存放位置：

| 字段 | 内容 |
|---|---|
| `skill_detail` | 技能类型（纯 tag id 数组） |
| `skill_effect[].effect_tag` | 技能效果行标签，**混合**三类：① 机制「包含效果」类（治疗 488、定值生命恢复 492…）；② 目标标签（友方防御塔 844…）；③ **升级来源**（神杖升级 1046、魔晶升级 1047、天赋 1048–1055、其他 1056、饰品 1101、命石 1165）——**结果表「升级项」列的数据来源即在此** |
| `skill_mechanism[].mechanism_tag` | 技能特性（技能行为 / 其他行为类） |
| `skill_mechanism[].mechanism_input` | **技能特性的内容**（该特性行的完整描述句，如「本技能的所有效果均不会被幻象继承。」）——**结果表命中技能特性时展示的正文即在此** |
| `tags` | 散列字段（与效果标签部分重合，**不含**目标标签） |

### 技能特性内容的存储与体积控制

特性文本在全库高度重复（同一 tag 常有十几种写法、单句出现上千次），因此 `data.js` 做了**池化**：

```js
window.TAGDB = {
  tags:     [{id, name, c1, c2}],
  featText: { "80": ["本技能的所有效果均不会被幻象继承。", "本技能不会被幻象继承", …] },  // tagId → 文本槽
  abilities:[{ i, n, en, d, g, m, e, f }]                                                   // f = 与 m 同序的池下标
}
```

- `build_data.py` 构建时把 `(tagId, 文本)` 去重入池，技能侧 `f` 只存下标 → 实测 **4042 次引用压成 118 个 tag / 1628 个文本槽**，`data.js` 仅从 607 KB 增至 775 KB（未池化约 1.1 MB）。
- 读取链路：`featTexts(index,a)` → 与 `a.m` 同序的文本数组；`featsOf(index,a)` → `[{id,name,text,c1,c2}]`。
- **旧 `data.js` 无 `featText` 时自动降级**：仍可正常检索，只是不显示特性内容（需点「⟳ 更新本地数据」重抓一次）。

## 八、依赖与开源说明

### 运行时依赖

| 用途 | 依赖 | 必需性 |
|---|---|---|
| 检索 / 浏览 / 导出 CSV | 现代浏览器（Chrome / Edge） | **必需** |
| 抓取数据（`refresh.sh`、一键更新） | [bsk（browser-skill）CLI](https://github.com/Tencent/BrowserSkill) + 浏览器扩展 + 后台登录态 | 仅更新数据时需要 |
| 构建 `data.js`（`build_data.py`） | Python 3.8+ | 仅更新数据时需要 |
| `selftest.js` / `uitest.js` | Node.js 18+（`uitest.js` 另需 `jsdom`） | 仅测试时需要 |

### 数据说明

- 仓库**不包含**任何抓取数据：`data.js`、`_raw.json` 均已写入 `.gitignore`。
- 数据来自站点后台接口，抓取依赖**你自己的登录态**；本项目不提供、不代理、不再分发该数据。
- 使用抓取功能前，请自行确认符合站点使用条款。

### 目录结构

```text
tagsearch/
├── index.html              主界面（单页应用）
├── search-core.js          检索内核（浏览器 / Node 通用）
├── icons/                  升级项图标 1046–1055.png
├── scripts/fetch_tagdb.js  页面内抓取脚本
├── refresh.sh / refresh.bat 一键抓取 → 重建 data.js
├── build_data.py           _raw.json → data.js（技能特性内容池化）
├── serve.py / start.bat    本机服务 + 一键更新
├── selftest.js / uitest.js 自测与界面回归
└── .gitignore              数据快照、缓存不入库
```
